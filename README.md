# AegisGate Enterprise — AI Agent Security Gateway & Validation Lab

**A practical 1–2-day, local-only portfolio lab** connecting AI agent tool use with enforceable authorization, persistent audit logging, security detections, and automated evaluations.

> ⚠️ This is a **training prototype**, not production security. `/demo/login/{user}` lets anyone impersonate a fictional user. Run only on loopback with synthetic data. Do not use real company documents, expose it publicly, or claim real authentication.

## What you will learn
- Why AI instructions are not authorization controls.
- How to enforce permissions before tool execution.
- How to verify that denied actions produce no side effects.
- How to audit, detect, and evaluate unauthorized tool requests.
- How to integrate Claude and MCP without bypassing the gateway.

## Quickstart: VS Code + WSL Ubuntu
1. Install VS Code WSL + Python extensions and `uv`: https://docs.astral.sh/uv/getting-started/installation/
2. Extract ZIP into `~/projects/aegisgate` and open `code .` from Ubuntu.
3. `uv python install 3.12 && uv sync`
4. `uv run pytest -v`
5. `uv run python -m scripts.evaluate` (27 deterministic scenarios)
6. `uv run uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload`
7. Open http://127.0.0.1:8000/docs

## First API experiment (second WSL terminal)
```bash
BOB=$(curl -s -X POST http://127.0.0.1:8000/demo/login/bob | python3 -c 'import json,sys;print(json.load(sys.stdin)["access_token"])')
curl -i -X POST http://127.0.0.1:8000/tools/execute \
  -H "Authorization: Bearer $BOB" -H 'Content-Type: application/json' \
  -d '{"tool":"read_document","resource":"executive_report"}'
```
Expected: **403**. Use `/demo/login/carol` for a token that can read the report. This is **not** real login.

## Optional Claude mode
```bash
uv sync --extra ai
cp .env.example .env
# edit .env; insert real key and valid model ID
set -a; source .env; set +a
# restart API, then POST /agent/chat with {"prompt":"Investigate login events","mode":"claude"}
```
Claude API calls may cost money. The default `demo` mode is deterministic and free.

## Optional MCP server
```bash
uv sync --extra mcp
# Set AEGIS_MCP_DEMO_TOKEN to a demo token generated by the API
uv run python -m app.mcp_server
```
MCP is STDIO and should be connected via an MCP client. MCP bridge uses a **single server-held demo identity**; it does not delegate user identity. See `docs/THREAT_MODEL.md`.

## Optional dashboard
```bash
uv sync --extra dashboard
uv run streamlit run app/dashboard.py
```

## Docker
```bash
docker compose up --build -d
docker compose ps
```
API binds to `127.0.0.1:8000` on the host.

## Engineering proof
- `uv run pytest -v`: 21 tests for denied access, side effects, forged tokens, audit visibility, and detection.
- `uv run python -m scripts.evaluate`: **27 deterministic authorization scenarios**; not a claim about model-level prompt-injection attack success.
- `docs/THREAT_MODEL.md`: explicit threats and limitations.
- `.github/workflows/ci.yml`: automated tests and evaluation.

## 1–2 day execution
**Day 1:** setup → tests → API → permission lab → audit/detection → evaluation.
**Day 2:** optional Claude → optional MCP → dashboard → Docker → GitHub README and demo. If time is limited, prioritize tests and a polished demo over optional infrastructure.
